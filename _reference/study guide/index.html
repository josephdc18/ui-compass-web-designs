Embedded + Memory Fundamentals

What "Memory-Mapped I/O" Means

On STM32, GPIO pins aren't magic pins — they're controlled by peripheral registers. Those registers are placed ("mapped") into the same address space as normal memory.

Key Takeaway: Your CPU can read/write them like variables.

Address Bus → Address Range

Your STM32 has a 32-bit address bus.

  • Range: 0x0000_0000 to 0xFFFF_FFFF
  • Capacity: 4,294,967,296 possible addresses ≈ 4 GB address space.

GPIO Registers You Should Recognize

Match the register name to its purpose:

MODER - Mode register
OTYPER - Output type
OSPEEDR - Speed
PUPDR - Pull-up/pull-down
IDR - Input read
ODR - Output write
BSRR - Bit set/reset

Also worth recognizing: AFRL/AFRH, LCKR, and related GPIO control registers.

Embedded C Survival Kit

2.1 stdint.h - Why Professors Love It

A plain int can be 2 bytes on one system and 4 bytes on another. stdint.h eliminates ambiguity and prevents hidden portability bugs.

  • uint8_t
    1 byte (8 bits)
  • uint16_t
    2 bytes (16 bits)
  • uint32_t
    4 bytes (32 bits)

2.2 Pointers

A pointer stores an address, not a value.

  • &x - address of x
  • *p - value at address p (dereference)

2.3 Pointer Size

Pointer size depends on the architecture's address size (CPU/address width).

On 64-bit systems, pointers are usually 8 bytes regardless of pointee type. They must be wide enough to hold any valid address.

  • PC (x86_64) 8 bytes
  • STM32 (32-bit) 4 bytes

Quiz trick: "Pointer size depends on architecture."

2.4 Casting Addresses

To treat a raw number as an address, typecast it.

// address of some register
uint32_t *reg = (uint32_t*) 0x40020000;
// write to that register
*reg = 0x1;

Common Traps

Common Trap: volatile vs const

Wrong assumption: Use const for hardware registers because they should not change.

Why wrong: Register values can change outside your code path; const blocks required writes and does not force fresh reads.

Correct pattern: Use volatile for memory-mapped register access. Combine with const only when truly read-only from firmware.

Common Trap: Pointer Size Myth

Wrong assumption: Pointer size depends on the type it points to.

Why wrong: Pointer width follows architecture address width, not pointee type.

Correct pattern: Remember: x86_64 pointers are typically 8 bytes; 32-bit STM32 pointers are typically 4 bytes.

Bitwise Operations + Shifts

"Set/clear/check bits inside registers."

The Operators

  • & AND - masking/checking
  • | OR - setting bits
  • ^ XOR - toggling bits
  • ~ NOT - inverting bits
  • << >> Shifts - moving bits

4 Patterns to Memorize

Set bit n
REG |= (1U << n);
Clear bit n
REG &= ~(1U << n);
Toggle bit n
REG ^= (1U << n);
Check bit n
if (REG & (1U << n))

3.2 How Shifts Help Decode 32-Bit Packets

Moves the target field to bit 0, then mask isolates it.

Example: Extract Packet field [12:9] (4 bits)

  1. Shift right by 9.
  2. Mask 4 bits (0b1111 = 0xF).
field = (packet >> 9) & 0xF;

This shift-then-mask pattern is reused constantly when decoding packed 32-bit data fields.

Wrong assumption: Use OR to toggle a bit.

Bare-Metal GPIO Mechanics

Controlling an LED (like PA5) requires writing peripheral registers.

Enable Peripheral Clock: Without it, the peripheral won't accept configurations.

2

Set Pin Mode: Use the MODER register to set to output.

3

Write HIGH/LOW: By writing to ODR or BSRR.

The MODER Concept (Frequent MCQ)

In STM32 GPIO, each pin uses two bits in MODER to select its mode (input, output, alternate, analog).

Example: Pin 5 uses bits [11:10]. Code often clears 2 bits then sets them.

5.2 Padding & Packing

Compilers insert "padding" bytes so data aligns on natural boundaries. This wastes SRAM and creates unused gaps between members.

Packed Structures

__attribute__((packed)) removes padding. Saves memory, but may slow down access.

Structs + Bit-Fields

Useful for decoding 32-bit packets, reducing memory usage, and grouping related bits into named fields.

HAL Drivers

HAL (Hardware Abstraction Layer) lets you write portable code using APIs rather than raw addresses or manual register bit-manipulation.

STM32 header files already define peripheral base addresses and overlay structures used by HAL and low-level code.

6.2 HAL GPIO Init Pattern

  1. Create an initialization struct.
  2. Fill its fields (Pin, Mode, Pull, Speed).
  3. Call HAL_GPIO_Init() to configure registers.

6.3 "Handle" Structures

For complex peripherals (UART), HAL uses a handle to store:

  • Base register address (Instance)
  • Init parameters
  • Pointers to TX/RX buffers
  • Counters/state variables
Handle = State + Configuration

Interrupts

7.1 What Happens - Big Picture

An interrupt starts when EXTI detects a rising/falling edge.

EXTI signals NVIC NVIC sets pending bit NVIC checks priority Runs highest-priority ISR

The CPU then locates the ISR through the vector table and jumps to it.

7.2 HAL Interrupt Flow (Memorize This)

EXTI0_IRQHandler
IRQ Handler (main.c)
HAL_GPIO_EXTI_IRQHandler
Driver: Clears flags
HAL_GPIO_EXTI_Callback
User Code (main.c)
  • IRQ handler in main.c calls HAL's IRQ handler.
  • HAL IRQ handler clears interrupt flags and calls the callback.
  • The callback is where your response code runs (for example, toggling an LED).

7.3 Steps to Configure GPIO Interrupt

  1. 1 Configure pin as input
  2. 2 Select edge trigger
  3. 3 Enable EXTI (NVIC delivery)
  4. 4 Identify IRQ number
  5. 5 Set IRQ priority
  6. 6 Enable IRQ reception
  7. 7 Write IRQ handler

Worked Exam Problems

Consolidated worked Q&A set with near-verbatim steps and explanations.

1) Pointer size on a "16-bit memory bus"

Question: For a 16-bit memory bus, how much memory is allocated for the pointer variable data?

uint32_t* data;

a. 1 byte
b. 2 bytes
c. 4 bytes
d. 8 bytes

Answer: c) 4 bytes

  1. data is a pointer, so it stores an address, not a uint32_t value.
  2. Pointer size depends on CPU/address size (how many bits represent an address), not on the pointee type and not directly on memory bus width.
  3. In this quiz context (later questions use 32-bit addresses like 0x40080B00), addresses are 32-bit, so a pointer needs 32 bits = 4 bytes.
2) Values after pointer assignment and dereference

Question: The following statements are executed:

uint8_t data1 = 0xD2;
uint32_t* data2 = (uint32_t*) 0x00D3A894;
*data2 = 0xB6;

/* The compiler stores data1 at location 0x40080B00 */

Find: data1, data2, data1++, data2++, *data2, &data1, byte at 0x40080B00, byte at 0x00D3A894.

State after the 3 statements:

  • data1 = 0xD2 (8-bit value)
  • data2 = (uint32_t*)0x00D3A894
  • *data2 = 0xB6 writes a 32-bit value, so 0x000000B6 is written at 0x00D3A894 (4 bytes).

Assumption: typical ARM systems are little-endian, meaning the least-significant byte goes at the lowest address.

a) data1: 0xD2

b) data2: 0x00D3A894

c) data1++: expression evaluates to 0xD2, then data1 becomes 0xD3.

d) data2++: expression evaluates to 0x00D3A894, then data2 becomes 0x00D3A898 because sizeof(*data2) = 4.

e) *data2: 0x000000B6 at 0x00D3A894.

f) &data1: 0x40080B00

g) Byte at 0x40080B00: 0xD2

h) Byte at 0x00D3A894: 0xB6 (little-endian)

0x00D3A894: 0xB6
0x00D3A895: 0x00
0x00D3A896: 0x00
0x00D3A897: 0x00

Note: post-increment changes later state; unless an explicit sequence is given, treat subparts independently.

3) Interrupt function execution order (EXTI0)

Question: Order the following from 1 to 3:

  • HAL_GPIO_EXTI_Callback()
  • HAL_GPIO_EXTI_IRQHandler()
  • EXTI0_IRQHandler()

Answer:

  1. EXTI0_IRQHandler()
  2. HAL_GPIO_EXTI_IRQHandler()
  3. HAL_GPIO_EXTI_Callback()

Why: NVIC dispatches to ISR first, ISR calls HAL handler, HAL handler then calls callback.

4) Function that determines what caused the interrupt

Question: Which function is used to determine the specific events that resulted in the interrupt being generated?

a. HAL_GPIO_EXTI_Callback()
b. HAL_GPIO_EXTI_IRQHandler()
c. EXTI0_IRQHandler()

Answer: b) HAL_GPIO_EXTI_IRQHandler()

  1. This stage checks pending/flag bits to identify interrupt source details.
  2. The HAL IRQ handler checks/clears EXTI pending status and routes to callback.
5) Function that communicates the interrupt event to user code

Question: Which function communicates the interrupt event to the user executable program so proper action can be taken?

a. HAL_GPIO_EXTI_Callback()
b. HAL_GPIO_EXTI_IRQHandler()
c. EXTI0_IRQHandler()

Answer: a) HAL_GPIO_EXTI_Callback()

  1. The callback is the user-level hook where application behavior lives.
  2. HAL calls it after source identification and flag handling.
6) First function called when NVIC registers the interrupt

Question: Which is the first function called when an interrupt is registered by NVIC?

a. HAL_GPIO_EXTI_Callback()
b. HAL_GPIO_EXTI_IRQHandler()
c. EXTI0_IRQHandler()

Answer: c) EXTI0_IRQHandler()

  1. NVIC dispatches to the vector-table entry for EXTI0.
  2. That vector points to EXTI0_IRQHandler().
7) Bit operations on a 32-bit register via *pData

Question: Write code to (a) clear bits 4 and 5, and (b) set bits 27, 28, and 29.

a) Clear bits 4 and 5

*pData &= ~(0x3U << 4);
  1. Bits 4 and 5 are a 2-bit field: (0x3U << 4).
  2. Invert the mask so only those bits are zeroed in mask.
  3. AND assignment clears bits 4-5 and preserves others.

b) Set bits 27, 28, and 29

*pData |= (0x7U << 27);
  1. Bits 27-29 are a 3-bit field: 0x7.
  2. Shift into place: (0x7U << 27).
  3. OR assignment sets these bits to 1 and leaves others unchanged.
8) Pointer cannot change, but pointed-to data can change anytime

Question: Fill qualifiers:

uint32_t ______ * ______ pData = (uint32_t*) 0x40000000

Answer:

volatile uint32_t * const pData = (volatile uint32_t *)0x40000000;
  1. Pointed-to data may change anytime: make pointee volatile.
  2. Pointer value must not change: make pointer itself const.
9) Three configurable GPIO pin parameters

Question: Name three configurable parameters of a GPIO peripheral pin.

Answer (examples):

  • Mode (input / output / alternate function / analog)
  • Pull configuration (no-pull / pull-up / pull-down)
  • Output type (push-pull / open-drain)

These control the electrical/functional behavior of the pin (along with options like speed and alternate function selection).

10) Register pointer mapping + bit operations (use volatile and const)

a) Map pGPIOD_IDR to GPIOD IDR and read bit 8 into uint8_t pin8Data

volatile uint32_t * const pGPIOD_IDR =
    (volatile uint32_t *)(0x40020C00UL + 0x10UL);   // GPIOD base + IDR offset

uint8_t pin8Data = (uint8_t)((*pGPIOD_IDR >> 8) & 0x1U);
  1. IDR address = base 0x40020C00 + offset 0x10 = 0x40020C10.
  2. volatile because hardware register values can change outside normal flow.
  3. const on the pointer so the address mapping itself is fixed.
  4. Read bit 8 by shifting right 8 and masking with 0x1.

b) Map pGPIOB_Mode to GPIOB MODER and clear bits 10 and 11 to 00

volatile uint32_t * const pGPIOB_Mode =
    (volatile uint32_t *)(0x40020400UL + 0x00UL);   // GPIOB base + MODER offset

*pGPIOB_Mode &= ~(0x3UL << 10);
  1. MODER address = GPIOB base 0x40020400 + offset 0x00.
  2. Bits 10 and 11 form a 2-bit field, so mask is (0x3UL << 10).
  3. Invert mask and AND to force those bits to 00 while preserving others.

Bitwise Patterns

Set bit n:    REG |=  (1U << n);
Clear bit n:  REG &= ~(1U << n);
Toggle bit n: REG ^=  (1U << n);
Check bit n:  if (REG & (1U << n))

Field [h:l]:  (value >> l) & ((1U << (h - l + 1)) - 1)

GPIO Register Purpose Map

  • MODER -> pin mode (input/output/AF/analog)
  • OTYPER -> output type
  • OSPEEDR -> output speed
  • PUPDR -> pull-up/pull-down
  • IDR -> read input pin state
  • ODR -> write output state
  • BSRR -> atomic set/reset

Interrupt Chain

EXTI -> NVIC -> ISR -> HAL_GPIO_EXTI_IRQHandler -> HAL_GPIO_EXTI_Callback

  • EXTI detects edge, signals NVIC.
  • NVIC checks priority and dispatches IRQ.
  • ISR calls HAL IRQ handler.
  • HAL clears flags and invokes callback.

Common Formulas + Facts

  • 32-bit address space: 0x0000_0000 to 0xFFFF_FFFF
  • uint8_t/16_t/32_t are fixed-width integer types.
  • Pointer size depends on architecture (x86_64: 8 bytes, STM32: 4 bytes).
  • volatile prevents optimizer from removing hardware reads/writes.
  • . for struct variable, -> for pointer to struct.
  • Padding may make struct size larger than member sum.
